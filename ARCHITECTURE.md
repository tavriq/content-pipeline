## 2. ЧТО КУДА КЛАДЁТСЯ

| Что | Куда | Почему туда |
|---|---|---|
| Красные линии | `CLAUDE.md` | читается всегда, скилл может не подгрузиться |
| Роль редактора | `core/system-prompt.md` | подтягивается скиллами, не грузится каждый сеанс |
| Решения | `CONTEXT.md`, таблица | один источник, `status.py` читает оттуда |
| План, юридическое | `docs/` | нужно редко, читается по запросу |
| Готовые материалы файлового трека | папка по статусу | состояние выводится из файловой системы |
| Материалы контентного конвейера | PostgreSQL, файл после публикации | база — рабочее состояние, git — архив вышедшего |
| Реестр тем блога | `core/topics.yaml`, копия в базе | файл читает человек, база — конвейер; статус возвращается в файл |
| Видео, футажи, экспорты | облако, в гите только ссылка | иначе репозиторий распухнет |
| Токены, ключи | `.env`, в `.gitignore` | и `.env.example` рядом для памяти |
| Новости, дайджесты, версии, расписание | PostgreSQL через `db/migrations/` | транзакции, история правок и надёжный планировщик |

**Правило одного экземпляра.** Красные линии существуют в одном месте. Реестр тем — в одном. Журнал решений — в одном. Любая копия разойдётся с оригиналом в течение месяца, и обнаружится это в худший момент.

**Правило веса `CLAUDE.md`.** Он читается при каждом сеансе. Всё, что там лежит, вы платите постоянно — токенами и размыванием внимания агента. Туда идут только красные линии, конвейер и команды. Остальное — ссылками через `@`, агент прочитает, когда понадобится.

## 3. ЕСЛИ ВСЯ РАБОТА ПЕРЕЕЗЖАЕТ В CLAUDE CODE

Схема с двумя чат-проектами перестаёт быть нужна, но три вещи придётся сделать иначе.

### 3.1. Роль редактора приезжает из скилла

Раньше её задавали инструкции проекта. Теперь — первая строка каждого контентного скилла: прочитать `core/system-prompt.md` и `core/red-lines.md`. Если этого нет, материалы будут генерироваться без роли, и заметите вы это не сразу, а на десятом ролике.

Проверка: попросите сгенерировать сценарий и посмотрите, есть ли поля `источник` и `требует_проверки`. Нет — скилл не читает промпт.

### 3.2. Стратегические разговоры тоже идут в репозиторий

В чат-проектах обсуждение оставалось в чате. В Claude Code сеанс закрывается — и разговора не было. Значит: любой заход, где принято решение, заканчивается строчкой в `CONTEXT.md`. Не «потом запишу».

Практически это одна фраза в конце: «запиши принятое в CONTEXT.md». Приучите себя к ней сразу, иначе через месяц половина решений будет жить только у вас в голове.

### 3.3. Разделение по ролям — через скиллы, не через окна

Раньше техничка и продакшн были разными проектами. Теперь это один репозиторий, и разделение держится дисциплиной:

- работа над кодом — только когда есть заявка с цифрой («трачу сорок минут в неделю на X»);
- работа над контентом — через скиллы, которые не трогают `scripts/`.

Формально это можно закрепить: в `CLAUDE.md` строчкой «не предлагай улучшения пайплайна, если я не спросил про пайплайн». Помогает меньше, чем дисциплина, но лишним не будет.

### 3.4. Что теряется

Чат удобнее для длинных нащупывающих разговоров — про стратегию, позиционирование, формулировки. В Claude Code это тоже работает, но соблазн сразу писать файлы мешает думать.

Разумный компромисс: репозиторий — рабочее место, чат оставить для двух вещей. Первое — обсуждения, где ещё нет ответа и не должно быть файла. Второе — доступ с телефона, когда нужно что-то посмотреть или обсудить не за столом.

### 3.5. Что не переезжает

Cowork остаётся снаружи репозитория: сводки по метрикам, ресёрч рекламодателей, коммерческие документы. Два агента, редактирующих одно дерево с разным контекстом, — это конфликты и потерянные правки. Граница прежняя: внутри репозитория Claude Code, снаружи Cowork.

## 4. ЧЕГО В РЕПОЗИТОРИИ НЕТ

`claude_code_setup.md` и `plan_realizacii_blog_v*.md` — исходники, из
которых собран репозиторий. Их содержимое давно разложено по `CLAUDE.md`,
`core/` и `docs/`; сами файлы не хранятся. Ссылки на них в старых
документах читать как ссылки на `docs/pipeline.md` и `docs/plan.md`.

Скиллы `weekly-plan` и `from-voice` не сделаны сознательно — см.
`BUILD.md`, спринт 2.
